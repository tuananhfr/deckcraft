# ERPCons changes

- Media sound (web): audio and video soundtracks play through a Web Audio output (short buffers scheduled at the context's rate, unlocked by the gesture that starts playback); when the browser blocks or loses audio, audible media pause with a translated retry notice, shown once per failure, instead of playing silently. Desktop is unchanged.

- Undo/Redo (both): add Shift+Z Redo, platform tooltips, timestamped transaction history, reachable 44-point narrow-screen controls and save-history regression coverage.

- AutoRecover (both): retain recovered records until a durable checkpoint or explicit save/discard, deduplicate related checkpoints and fall back from corrupt newer records.

- Point the website links (About, installers, release notes) to https://office.erpcons.ai; app ids keep the `vn.erpcons.*` form.
- Desktop updates: check signed ERPCons releases automatically or from Help, preserve unsaved presentations, and download, verify and restart with installation notices and a settings preference; Windows MSI installation waits for Install now or Cancel.

- Finder open (macOS desktop): handle document and quit Apple events through the existing open and close paths; register .deckcraft, .pptx, .potx and .ppsx with document icons.

- Default apps (Windows): list Trình chiếu – ERPCons in Settings > Default apps for .deckcraft, .pptx, .potx and .ppsx; it still owns only .deckcraft and never takes over PowerPoint formats.
- Desktop installers (desktop): build unsigned Windows, ad-hoc signed universal macOS and Linux packages in GitHub Actions; publish fixed download names and checksums for validated ERPCons version tags.
- ERPCons branding (desktop): use Trình chiếu – ERPCons, isolated ERPCons/TrinhChieu storage, ERPCons icons and installer identities; preserve web branding and binary names.

- Rich clipboard (desktop): copy HTML with plain text and read native HTML on paste through arboard, with plain-text fallback and existing session clipboard preservation.
- Save picker (desktop): default new presentations to .pptx, retain opened formats and offer .deckcraft alongside .pptx; keep loss warnings.
- Recovery notices (desktop): show a translated warning on recovery failure and translate recovered presentation counts.
- File dialogs (desktop): translate presentation, picture, audio and outline filters into Vietnamese.

- Selected-object typing (both): keep table typing in the first selected cell (or the first cell of the whole table), including IME input; ignore typing and IME on pictures and other objects without text instead of showing raw command errors.
- Light-theme inputs (both): use existing palette tokens for visible input, checkbox and combo-box borders and checkmarks, with at least 3:1 contrast against panels and fields; dark-theme visuals are unchanged.
- Vietnamese product name (both): translate the product name as "Trình chiếu" throughout the Vietnamese catalog, preserving the original copyright credit; add a catalog regression check.

- Legacy presentation notices (both): OLE2/.ppt and .odp open a translated conversion dialog instead of a status message; .pptm opens with a macro-loss notice, and Save/Save As propose .pptx and preserve the legacy original.
- Font substitution notice verification (both): regression coverage checks the existing dismissible toast appears once per opened presentation, including tab switches, and lists at most three font names followed by the remaining count.

- Slide show fullscreen (web): request browser fullscreen when the show starts, continue windowed if refused, release fullscreen on every show exit, and end the show when browser fullscreen is left; Presenter View opens only through its explicit command.
- Touch slide show exit and translation (both): a persistent top-right 44-point close target ends the show with the Vietnamese tooltip "Thoát trình chiếu"; the End control reads "Kết thúc trình chiếu" in Vietnamese.

- Close waits for Save (web): closing a presentation waits for the pending browser write; cancelled or failed saves and edits made during saving keep it open, and browser save errors use translated messages without raw exception details.
- Narrow-screen close button (both): the title bar keeps a document × reachable at 390 points, with the translated Close document tooltip and the existing Save / Don't Save / Cancel flow.
- Editor closed hook (web): after the last open presentation is explicitly closed, call the optional ERP shell's no-argument `window.erpEditorClosed` once; standalone pages and desktop need no hook.

- Loss warnings before Save, Save As and Export (both): one translated dialog lists OLE objects reduced to previews, removed digital signatures and macros, and discarded part kinds; Save Anyway proceeds once, Save a Copy preserves the open document's name and saved state, and Cancel writes nothing, including before browser saves start.

- Removed the ArtCraft logos and marks (`docs/brand/`) and every link to the ArtCraft Discord and getartcraft.com, as the ArtCraft brand terms require for forks: About dialog, Backstage Home and Account, the ribbon's "Learn More" group, `app.links`, the CLI and the MCP server info, README.
- About now reads "ERPCons Văn phòng — dựa trên DeckCraft của nhóm ArtCraft. MIT OR Apache-2.0."; source links point at this fork.
- On a host with no save dialog (the web build), Save and Save As download a `.pptx` for every presentation, including new ones and `.deckcraft` files, and the download marks the presentation saved. Desktop builds still default to `.deckcraft`.
- Input methods that rewrite letters already typed (Vietnamese Telex/VNI in a browser, phone keyboard corrections) no longer garble slide text ("aá" for "á"): egui's `DeleteSurrounding` IME event runs the new `text.deleteSurrounding` command (`Session::delete_surrounding`), which deletes around the insertion point or composition within the paragraph; the replacement that follows (text, or a preedit and commit) is one undo step with the deletion.
- The web build asks before the tab is closed, reloaded or left while a presentation has unsaved changes or a save is still in the save picker (`beforeunload`).
- On browsers with a save picker (`showSaveFilePicker`, Chromium), web Save and Save As write through it (`Services::save_file`) and mark the presentation saved only once the file is written, as it was when written: cancelling keeps the changes unsaved, a failure says why in the status bar, and edits made while the picker was open stay unsaved. Other browsers keep the download, which marks it saved at once.
- Web draft autosave: when the page provides the office site's draft store (`window.erpDrafts`), unsaved presentations (dirty, or a save still in flight) are put there as native `.deckcraft` bytes under `doc-<uid>` and the name `<title>.pptx` after 2.5 s without edits, at least every 30 s while editing goes on, never more often than ten times the last serialization, and at once when the page is hidden; not while an input method composes. A draft is removed once its presentation is saved, undone back to saved or closed. Drafts the store hands back open unsaved under their name and keep the store's key (`drafts.rs` in `deckcraft-ui-egui`, `draft_bridge.rs` in the web app). Without the store nothing changes; the desktop AutoRecover is untouched.
- Vietnamese interface (`crates/ui-egui/src/i18n`, WordCraft's catalog format and lookup): ribbon, menus, dialogs, panes, Backstage, status bar and command labels are translated where drawn; command search still matches the English labels. The language is the `language` UI setting, changed with the `view.language` command or View › Interface Language. The web build starts in Vietnamese and keeps the choice in `localStorage` under `erpcons-ui-language`, shared with the other ERPCons editors (`auto` follows the browser).
- Office keyboard shortcuts: F1 opens Help › Keyboard Shortcuts, a searchable list of every shortcut (keys in Windows notation, command names in the interface language) built from the tables the key dispatch reads (`menus::UI_SHORTCUTS`, the command registry, `keys::EXTRA_SHORTCUTS`); Ctrl+M adds a slide (Ctrl+Shift+N still does); F12 is Save As. New Find and Replace: Ctrl+F opens a window that stays open beside the slide in Find mode, Ctrl+H in Replace mode; it searches the text of every slide's shapes, table cells and speaker notes, with Match case and Find whole words only. Find Next selects the next match (slide, shape, text) and wraps around, Replace replaces the selected match and finds the next, Replace All says how many it replaced; each replacement is one undo step (`edit.find`, `edit.replace`, `edit.replaceAll`). The command palette moves from Ctrl+F to Alt+Q (Ctrl+Shift+P still opens it).
- Document tabs: with two or more presentations open (opened, dropped, created, restored from drafts or AutoRecover), a row of tabs under the title bar shows each one with its name (shortened with "…", the full name on hover), a dot when it has unsaved changes and a × (`doctabs.rs`). Clicking a tab switches to it (`window.next {index}`); × or a middle-click closes that presentation (`file.close {index}`), asking about unsaved changes first, and closing another tab keeps the active one. With one presentation the window looks as before. At most 10 presentations are open at once: an 11th, by any path, is refused with "You can have up to 10 documents open. Close one to open another." (Vietnamese: "Chỉ mở được tối đa 10 tài liệu. Hãy đóng bớt một tài liệu để mở tài liệu khác.") in a notice and the status bar (`Session::add_document`, `MAX_DOCUMENTS`). Each presentation keeps its own zoom and scroll positions when switching.
- Zip packages from outside (PPTX/POTX/PPSX and native `.deckcraft`) inflate through one bounded reader, `deckcraft_model::inflate`, which checks what actually inflates rather than what the headers declare: an entry inflating more than 200:1 once past 4 MiB, an entry or a package over its cap (already when a header declares it), or too many entries refuses the whole file, even when the part was a picture or another optional part, with "The file is too large or abnormally compressed, so it can't be opened." ("Tệp quá lớn hoặc bị nén bất thường nên không mở được.") in a notice and the status bar (`EngineError::FileTooLarge`). Desktop keeps the limits it had (512 MiB per PPTX part, 2 GiB per native medium, 50,000 entries) and caps a package at 2 GiB; the web build allows 256 MiB per PPTX part and 512 MiB per native medium and per package, since the media stay inflated while the presentation is open. Buffers grow with `try_reserve`, so a failed allocation is that error rather than a crashed tab.
- `deny.toml`: a cargo-deny policy matching PdfCraft's (permissive licences only, crates.io as the only source, no wildcard requirements, RustSec advisories with a written reason for each ignore). Run with `cargo deny check`.
- Phones and tablets: below 600 points of window width (`narrow::NARROW_WIDTH`; a tablet in portrait stays wide) the ribbon folds to its tab row and the slide thumbnails hide, once, when the width crosses the breakpoint; tapping a tab unfolds the ribbon and the status bar's Slide Thumbnails switch (`view.thumbnails`) brings the thumbnails back, and those choices hold until the width crosses again, when the wide window gets its own back (the desktop saves its wide ribbon choice). Thumbnails and task panes opened in a narrow window float over the slide instead of squeezing it. The ribbon tabs, the ribbon's groups and, with more presentations than fit, the document tabs scroll sideways instead of being cut off. A narrow title bar drops the appearance switch, Comments, Play from Start, Home and Redo as room runs out and shortens the title with "…" so nothing overlaps the Present button; a narrow status bar keeps the slide counter (or a fresh message), the thumbnails, notes and comments switches, the zoom and Fit. On a touch screen (`touch.rs`): one finger dragged on an empty spot or an unselected shape pans a zoomed-in slide and never moves a shape, a tap selects (a click), dragging an already selected shape or its handles moves or sizes it, with a larger hit tolerance for a finger, a long press selects what is under the finger and opens its context menu, and two fingers pinch-zoom; in the slide show a swipe changes slides and a long press opens a Next Slide / Previous Slide / End Show menu (a right-click still goes back a slide), and a narrow window shows no Presenter View over the show. Mouse and pen input is unchanged.
- Touch fling, tablet status bar, translated prompts: on a touch screen a quick one-finger pan of a zoomed-in slide keeps going after the finger lifts and slows to a stop (GridCraft's fling: from 250 points/s, losing 4× its speed per second, ending under 20 points/s); it stops at the slide's edge, at a new touch or when the mouse moves (`touch::Fling`); the slide show's swipe is unchanged. A status bar too narrow for all its items (a tablet at 768 points with the longer Vietnamese labels, or a fresh message) lets them give way, lowest priority first, instead of overlapping: the proofing language, the zoom slider, the Notes and Comments words (their icons stay), the view buttons, then Zoom In and Zoom Out; a long message is cut with "…" (`status_fit.rs`). A 1366-point window shows everything as before. The prompts of empty placeholders ("Click to add title", subtitle, text, and the chart, table, SmartArt, media and picture prompts) are drawn in the interface language on the canvas (`RenderOpts::prompt_text`); they are only drawn, never stored, so saved PPTX files are unchanged.
- The built-in sample (and the web build's `?blank` start presentation) no longer takes one of the 10 open-presentation slots while untouched (`DocState::placeholder`, `Session::add_document`): as the only presentation it is replaced by the next one opened, created or restored from drafts, as WordCraft replaces its blank start document; beside others it stays until the limit is reached and then gives way, so 10 presentations of the user's own always fit. Once edited (anything to undo or redo) or saved to a file on the desktop, it counts like any other. The File tab now keys on the active presentation's uid, so it still closes when a presentation takes the sample's place.
- `deny.toml`: the symphonia crates (audio decoding) are allowed under MPL-2.0 by name, one exception per crate, so `cargo deny check` passes and any other MPL dependency still fails; they are used unmodified and NOTICE links their source.
- Reopen, close several, save status: presentations closed in this session (most recent first, at most 10 and 64 MiB of native `.deckcraft` bytes together, the oldest dropped first; an untouched sample isn't kept) can be reopened with `file.reopenClosed` (Reopen Closed Presentation, "Mở lại tài liệu vừa đóng", Ctrl+Shift+T, listed under F1) as a new tab with their name and file, unsaved if they had unsaved changes, so a Don't Save by mistake loses nothing; the 10-open limit refuses it and keeps it to reopen (`closed.rs`, `Session::closed`). The document tabs' context menu (right-click or long press) has Close, Close Others ("Đóng các tài liệu khác"), Close All ("Đóng tất cả") and Reopen Closed Presentation, which the File tab's Home and Open pages also offer, disabled when nothing was closed. Close All, Close Others (`app.closeAll`, `app.closeOthers`) and closing the desktop window ask once for every unsaved presentation, listing them, with Save All, Don't Save and Cancel (`close_many.rs`; Close of one presentation still asks Save, Don't Save, Cancel): Save All saves them one after another, each only once the one before is written (on the web the next browser save picker opens on a click of its own, since a browser opens one only for a click or key); a cancelled or failed save stops there and nothing is closed. The title bar (and the tab's tooltip) says "Đang lưu…" while a save is in the browser's save picker or being written (on the desktop, Save writes in the frame after showing it) and "Lưu không thành công" after a failed save until the next successful save or edit, with the reason on hovering the title or, on a click or tap, in a notice; a phone's title shortens the name before the state. Notices now wrap within a phone's width (`save_state.rs`, `toast.rs`).
- Find and Replace match Vietnamese however it is encoded (both): text pasted decomposed (NFD, "e" followed by its combining marks, as some apps and macOS produce) and text typed precomposed (NFC) find each other, in either direction, in shapes, table cells and speaker notes; combining marks in any order are the same letter. Matching compares the canonical decomposition cluster by cluster (`cmd/textmatch.rs`, the MIT/Apache-2.0 `unicode-normalization` crate, which `cargo deny` accepts), so accents still count ("a" never finds "ả" or the "a" of "nhà"), Match case and Find whole words work as before, and the selected match and what Replace and Replace All replace are the whole letters in the stored text, however many more chars the decomposed form has. Stored text is never normalized: what is not replaced keeps its encoding.
- Typing on a selected table (both) goes into a cell instead of showing the English error "invalid parameters for `text.edit`: say which `cell` of the table": the first of the selected cells, else the table's first cell, has its text replaced by what is typed, as on any selected shape; Enter, F2 and Edit Text on a selected table start editing that cell too (`text.edit` without `cell`).
- Clipboard shortcuts (web only): Ctrl/Cmd+C, X and V run once when the browser sends both key and clipboard events, so a paste creates one copy and needs one Undo. Ctrl/Cmd+Shift+V keeps Paste and Match Formatting and ignores a duplicate Paste event in the same frame.
- Web clipboard bridge (web): capture HTML, RTF, plain text and bounded images in one paste, expose rich data for one frame, route ribbon/context Paste through the browser clipboard, and copy/cut escaped HTML plus plain text without a second write; empty copies preserve the system clipboard and denied reads/writes show translated notices. HTML reaches `edit.paste` with a single plain-text fallback until rich import is available.
- Rich copy and cross-tab paste (both): text selections export styled HTML paragraphs, tables and cell ranges export quoted TSV and HTML with merged cells, and copied shapes/slides carry a versioned, validated internal marker capped at 4 MiB with embedded media. Valid markers restore objects in another session with one Undo; invalid markers keep the plain-text fallback, and empty clipboard payloads never overwrite the system clipboard.
- Rich HTML and TSV paste (both): allow-listed clipboard HTML preserves formatted paragraphs, lists and safe links; HTML tables and multi-row TSV create real slide tables or fill and extend the selected table with merged cells, fill and bold. Placeholder replacement materializes inherited text formatting before removing its placeholder flag; each paste is one Undo. Bounded parsing strips active content and falls back to plain text on limits.
- Interface language (desktop): default to Vietnamese when no language was saved, preserve saved choices, and atomically save language changes immediately.
