# ERPCons changes

## 2026-10-30: Windows releases no longer ship deckcraft-cli

- (desktop, Windows) The MSI and the portable zip contain `deckcraft.exe` without `deckcraft-cli.exe`, whose `run --cmd … --save` and `mcp` edit presentations without the PI licence gate the app now enforces (owner decision, as pdfcraft and UbotCAD did). `packaging/windows/package.ps1` builds only `-p deckcraft`, checks, copies and signs only the app and no longer smoke-tests the CLI; `deckcraft.wxs` drops the `DeckcraftCli` component, so the major upgrade removes the copy earlier MSIs installed. `erpcons-office`'s `build/desktop-win.sh` stops cross-building it. The crate stays in the workspace (tests, `cargo xtask` gates, development and agents). macOS, Linux and FreeBSD packaging still include it; they are not released by ERPCons.

## 2026-10-30: Editing needs a PI lease on the desktop (erpcons-account v0.5.0)

- `erpcons-account` and its dev-dependency `pi-mock` move to v0.5.0 (ADR 0013: the four Office apps are one PI product, `erpconsoffice`, with one device registration and one lease per machine). The desktop turns `Config::offline_licensing` on (`apps/deckcraft/src/account/config.rs`); releases verify leases with the pinned `PLATFORM_KEYS` (`lease-2026-10`, a compile-time check keeps it non-empty), debug builds also pin `ERPCONS_PI_DEV_LEASE_KEY` (`kid:hex32`, read at run time) for pi-mock or a local PI. The issuer is still read at build time from `ERPCONS_PI_ISSUER` (`ERPCONS_PI_API_BASE` optional) in `apps/deckcraft/src/account.rs`; builds without it install no account and are not gated.
- Licence lock (desktop only): opening, viewing, the slide show, Save, Save As, Export, Print and copying always work; every change needs `erpconsoffice.use` in an active lease of this device and `allowed(OFFICE_USE)`. The reason follows the library's state in this order (`apps/deckcraft/src/account/gate.rs`): guest or signing in "Sign in with PI ID to edit" ("Đăng nhập PI ID để sửa"); personal context "Choose an organization to edit" ("Chọn tổ chức để sửa"); then device revoked, device limit, no plan (`NotEntitled`, or a lease without `use`), not activated, no credential store, lease expired offline ("connect to renew") or online ("could not renew, the app keeps trying"); before the account is read "Checking your PI ID license…" (not announced, only given on a refusal and in File › Account); and an account that could not be opened, or a run with `DECKCRAFT_NO_PREFS` in a build with an issuer, stays locked as "unavailable" instead of failing open.
- The lock is the view mode of the office site's v2 (`Access`): ribbon greyed, refusals say the reason in the status bar instead of "You can only view this presentation.", the reason is said once when it starts and taken back when it lifts. `Access` gains `can_save` (`Access::edits_locked()`: not editable, Save, Save As, Export, Print and copying kept; `Access::read_only` keeps refusing Save as before), so the title bar's Save, Ctrl+S and File › Save stay for a locked presentation and save what was changed before the lock. `Session::set_new_document_access` makes presentations opened or created while locked start locked, also through the control server. `AccountHook` gains `edit_lock()` (read once per frame from cached state, before input and commands) and `edit_refused()`, both with defaults that never lock: the web adapter does not implement them, so the web build stays editable for everyone. Nothing is closed, reloaded or lost: text typed into a field is committed as one undo step when the lock starts, and a new lease gives editing back to the open presentations as they are (`crates/ui-egui/src/account/lock.rs`).
- File › Account: a guest reads the lock reason (the web keeps "Signing in is optional…") above Sign in; signed in, the reason sits under License with Retry where a sync or a new activation can lift it (organization, not activated, renewal, no plan, device limit). Retry syncs now and calls `retry_activation()` after a device-limit or not-entitled refusal. A refused edit that a sync may lift asks the worker for one, at most once a minute and backing off to an hour while it stays (cadcraft 1da7855); `take_refresh_request()` still queues `refresh()` on the worker. `is_pro_feature` now treats `<product>.use` as pro (only `.view` and `.export` are free); the licence line and the expiry warning follow the new `is_paid_feature` (pro, but not `.use`) instead, as in wordcraft and pdfcraft: the free plan, whose 7-day lease grants only `use` and renews itself while online, reads "Free" / "Miễn phí" and shows no 7/3/1-day warning, on the web too (a session listing `erpconsoffice.use` reads "Free"; the web's `allowed` fallback uses it as well, so the web never denies `use`). A lease granting a paid feature still gets the warning; its lines read "Your license is valid until {date}." / "Your license is active." / "Your license expires on {date}. Connect to the internet to renew it." instead of "Paid features …", since editing ends with such a lease too.
- New strings (en → vi): the 11 reasons above plus the 3 reworded licence lines, all in `crates/ui-egui/src/i18n/vi.tsv` (DeckCraft's only catalog).
- Tests: engine `access` 13 (new: locked edits still save, new presentations start locked); ui-egui `account::lock` 6 + 1 ignored screenshot test (`lock_screenshots`, `DECKCRAFT_SHOTS`), account/access/i18n tests updated; desktop `account` 20 against pi-mock 0.5.0 (`Scenario::office_free`): guest locked, sign-in to the free plan activates once and unlocks and reads Free, its lease two days from expiry raises no warning, personal context asks for an organization then unlocks, a revoked device locks after the next sync, a lease expired offline locks and a refused edit's resync renews it, Retry activates once the organization has a plan, a refused edit resyncs without waiting for the hourly refresh, no account stays locked, config and dev key. Local gate (`erpcons-office/build/run.sh gate`, log `gate-pireal-deckcraft-20261030T100635Z-test.log`): rustfmt, workspace clippy, wasm32 clippy passed; workspace tests passed=1375 failed=0.

Typing and input methods do nothing, keys that would edit (Delete, Enter, Ctrl+B, Ctrl+Z…) give that notice and arrows don't nudge; on the slide a click selects the shape (into text too: no caret; Enter, F2 and a double-click don't enter the text either, and going read-only leaves the text being edited with the shape still selected), shown by a plain outline when copying is allowed and not at all otherwise, with no handles, so dragging moves, sizes, rotates or duplicates nothing, drawing tools fall back to Select and a double-click opens no Format pane; empty placeholders are drawn as in the show, without their prompt ("Bấm để thêm tiêu đề"…) and dashed outline, as PowerPoint's Reading view does (rendering only, the file is unchanged), and the notes pane and the notes page show no "Click to add" prompt; paste, dropped pictures, audio, video and outlines, undo and redo, Find's Replace (Ctrl+H opens Find), comments' New, Reply, Resolve and Delete, the notes and outline fields (shown read-only), the dialogs that would change it (Table, Header & Footer, Spelling, Custom Show, Set Up Slide Show…) and the context menus (only Copy) are refused or not offered; a hidden object picked in the Selection pane is selected but stays hidden; the ribbon greys out what would be refused: the tabs that only edit whole (Insert, Draw, Design, Record and the shape, picture, table and chart tabs), the others' editing groups (Transitions and Animations but Preview, Hide Slide, Rehearse Timings, the show and media options, Slide Master's), and the Format, Background, Animation and Design Ideas panes are not offered (one already open shows greyed out); and Save, Ctrl+S and File › Save only give the notice. Navigation, zoom, view switches and the slide show keep working. AutoSave and Save send nothing for it, and `setMode` stops them inside the shell's call, a follow-up queued behind a save in flight included (that save still gets its answer). One opened read-only never becomes dirty and `flush` resolves at once for it; one downgraded with unsaved edits keeps them and stays dirty, and `flush` still hands it to `erpHost.save` (reason `flush`) under the same rules until it is saved or stopped by a conflict or a non-retryable failure. `setMode` changes an open document either way without reloading it: its content, unsaved edits and undo history stay, a gesture or composition in progress ends as one undo step, and so does text still typed into a field that commits on leaving it (speaker notes, the outline, the notes page, alt text, a shape's name, a property): the editor never drops an edit on its own, so the document is then dirty (`dirty(docId, true)`) for the shell's next `flush`, and back in `edit` AutoSave picks up where it was. `canDownload: false` (in any mode) refuses Save As, Export, Print, Share, Copy and Cut ("Downloading, printing and copying are turned off for this presentation.", "Bản trình bày này không cho phép tải xuống, in hoặc sao chép.") and drops Save As, Print and Export from File (an open one shows Info). `preserveView` on a document already open replaces its content in the same tab (`Session::replace_content`): same place, zoom and title updated, the current slide by position (slide ids don't survive a PPTX import) and the selected shapes still on it, the undo history dropped, the active tab unchanged; it is saved as of that version. `setUser({id, name})` names new comments and replies after the account (`Session::host_author`, never saved with the preferences); `null` goes back to the Author preference. - Online documents (web only, `window.erpHost` v1, erpcons-office `docs/erp-host.md`): when the page offers `erpHost` with `version === 1` (checked once at start-up), the app calls `erpHost.ready({open, flush, acknowledged})` once it can open files. `open(doc)` opens a .pptx from the server under its `title` (a `.pptx` suffix dropped) and reports `erpHost.opened(docId, ok, reason?)` once, with `reason` a key of the shell's intake messages, never text: `unsupported` (not pptx, a legacy .ppt/.odp or a password-protected file) or `parserFailed` (unreadable, `bytes` not a `Uint8Array`, or the 10-document limit); a second `open` of a document already open replaces its tab without asking (the shell reloads only when the user chose the server's version), or just shows it when it is that version unchanged. Such a document saves only to the server: AutoSave 3 s after the last edit and at the latest 30 s after the first unsaved one, Save / Ctrl+S / a close prompt's Save at once (`reason` `manual`), and `flush()` for every document whose revision differs from its acknowledged one (behind any save in flight; documents stopped by a conflict, a non-retryable failure or an unconfirmed loss warning are skipped), resolving once each is handed to `erpHost.save`, without waiting for the answers, and at the latest after 10 s; `erpHost.save(docId, bytes, {revision, reason})` gets the .pptx Save writes. One save is in flight per document and later triggers coalesce into one follow-up of the newest revision. The page's own leave-page prompt counts only local presentations: the shell guards its documents and learns of their saves first. AutoSave waits while a slide show, a drag or an input method composition is in progress (encoding a deck would stutter the show), and it and `flush` never save over a loss warning (OLE objects, signatures, macros, unsupported parts) until a Save confirmed those losses. On a touch screen (`touch.rs`): one finger dragged on an empty spot or an unselected shape pans a zoomed-in slide and never moves a shape, a tap selects (a click), dragging an already selected shape or its handles moves or sizes it, with a larger hit tolerance for a finger, a long press selects what is under the finger and opens its context menu, and two fingers pinch-zoom; in the slide show a swipe changes slides and a long press opens a Next Slide / Previous Slide / End Show menu (a right-click still goes back a slide), and a narrow window shows no Presenter View over the show. Mouse and pen input is unchanged.
- Touch fling, tablet status bar, translated prompts: on a touch screen a quick one-finger pan of a zoomed-in slide keeps going after the finger lifts and slows to a stop (GridCraft's fling: from 250 points/s, losing 4× its speed per second, ending under 20 points/s); it stops at the slide's edge, at a new touch or when the mouse moves (`touch::Fling`); the slide show's swipe is unchanged. A status bar too narrow for all its items (a tablet at 768 points with the longer Vietnamese labels, or a fresh message) lets them give way, lowest priority first, instead of overlapping: the proofing language, the zoom slider, the Notes and Comments words (their icons stay), the view buttons, then Zoom In and Zoom Out; a long message is cut with "…" (`status_fit.rs`). A 1366-point window shows everything as before. The prompts of empty placeholders ("Click to add title", subtitle, text, and the chart, table, SmartArt, media and picture prompts) are drawn in the interface language on the canvas (`RenderOpts::prompt_text`); they are only drawn, never stored, so saved PPTX files are unchanged.
- The built-in sample (and the web build's `?blank` start presentation) no longer takes one of the 10 open-presentation slots while untouched (`DocState::placeholder`, `Session::add_document`): as the only presentation it is replaced by the next one opened, created or restored from drafts, as WordCraft replaces its blank start document; beside others it stays until the limit is reached and then gives way, so 10 presentations of the user's own always fit. Once edited (anything to undo or redo) or saved to a file on the desktop, it counts like any other. The File tab now keys on the active presentation's uid, so it still closes when a presentation takes the sample's place.
- `deny.toml`: the symphonia crates (audio decoding) are allowed under MPL-2.0 by name, one exception per crate, so `cargo deny check` passes and any other MPL dependency still fails; they are used unmodified and NOTICE links their source.
- Reopen, close several, save status: presentations closed in this session (most recent first, at most 10 and 64 MiB of native `.deckcraft` bytes together, the oldest dropped first; an untouched sample isn't kept) can be reopened with `file.reopenClosed` (Reopen Closed Presentation, "Mở lại tài liệu vừa đóng", Ctrl+Shift+T, listed under F1) as a new tab with their name and file, unsaved if they had unsaved changes, so a Don't Save by mistake loses nothing; the 10-open limit refuses it and keeps it to reopen (`closed.rs`, `Session::closed`). The document tabs' context menu (right-click or long press) has Close, Close Others ("Đóng các tài liệu khác"), Close All ("Đóng tất cả") and Reopen Closed Presentation, which the File tab's Home and Open pages also offer, disabled when nothing was closed. Close All, Close Others (`app.closeAll`, `app.closeOthers`) and closing the desktop window ask once for every unsaved presentation, listing them, with Save All, Don't Save and Cancel (`close_many.rs`; Close of one presentation still asks Save, Don't Save, Cancel): Save All saves them one after another, each only once the one before is written (on the web the next browser save picker opens on a click of its own, since a browser opens one only for a click or key); a cancelled or failed save stops there and nothing is closed. The title bar (and the tab's tooltip) says "Đang lưu…" while a save is in the browser's save picker or being written (on the desktop, Save writes in the frame after showing it) and "Lưu không thành công" after a failed save until the next successful save or edit, with the reason on hovering the title or, on a click or tap, in a notice; a phone's title shortens the name before the state. Notices now wrap within a phone's width (`save_state.rs`, `toast.rs`).
- Find and Replace match Vietnamese however it is encoded (both): text pasted decomposed (NFD, "e" followed by its combining marks, as some apps and macOS produce) and text typed precomposed (NFC) find each other, in either direction, in shapes, table cells and speaker notes; combining marks in any order are the same letter. Matching compares the canonical decomposition cluster by cluster (`cmd/textmatch.rs`, the MIT/Apache-2.0 `unicode-normalization` crate, which `cargo deny` accepts), so accents still count ("a" never finds "ả" or the "a" of "nhà"), Match case and Find whole words work as before, and the selected match and what Replace and Replace All replace are the whole letters in the stored text, however many more chars the decomposed form has. Stored text is never normalized: what is not replaced keeps its encoding.
- Typing on a selected table (both) goes into a cell instead of showing the English error "invalid parameters for `text.edit`: say which `cell` of the table": the first of the selected cells, else the table's first cell, has its text replaced by what is typed, as on any selected shape; Enter, F2 and Edit Text on a selected table start editing that cell too (`text.edit` without `cell`).
- Clipboard shortcuts (web only): Ctrl/Cmd+C, X and V run once when the browser sends both key and clipboard events, so a paste creates one copy and needs one Undo. Ctrl/Cmd+Shift+V keeps Paste and Match Formatting and ignores a duplicate Paste event in the same frame.
- Web clipboard bridge (web): capture HTML, RTF, plain text and bounded images in one paste, expose rich data for one frame, route ribbon/context Paste through the browser clipboard, and copy/cut escaped HTML plus plain text without a second write; empty copies preserve the system clipboard and denied reads/writes show translated notices. HTML reaches `edit.paste` with a single plain-text fallback until rich import is available.
- Rich copy and cross-tab paste (both): text selections export styled HTML paragraphs, tables and cell ranges export quoted TSV and HTML with merged cells, and copied shapes/slides carry a versioned, validated internal marker capped at 4 MiB with embedded media. Valid markers restore objects in another session with one Undo; invalid markers keep the plain-text fallback, and empty clipboard payloads never overwrite the system clipboard.
- Rich HTML and TSV paste (both): allow-listed clipboard HTML preserves formatted paragraphs, lists and safe links; HTML tables and multi-row TSV create real slide tables or fill and extend the selected table with merged cells, fill and bold. Placeholder replacement materializes inherited text formatting before removing its placeholder flag; each paste is one Undo. Bounded parsing strips active content and falls back to plain text on limits.
- Interface language (desktop): default to Vietnamese when no language was saved, preserve saved choices, and atomically save language changes immediately.
